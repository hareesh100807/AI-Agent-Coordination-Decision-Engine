A. Current architecture summary:
The current system (Milestone 2) is a Flask-based web application (`web_app.py`) that collects expense data and passes it to a monolithic `Expense Audit Agent` (`app/agents/expense_audit_agent.py`). This single agent uses LangChain and Gemini to autonomously invoke two tools (`expense_policy_tool.py` and `receipt_validation_tool.py`) to gather policy data and validate receipts. It then formats a final audit report displayed via `audit_result.html`.

B. Files I intend to add:
1. `app/agents/coordinator_agent.py`: Will manage the multi-agent workflow, pass structured dicts between agents, and maintain short-term memory (a simple in-memory session context).

E. Brief explanation of how the new Milestone 3 workflow will work:
When an expense is submitted, `web_app.py` calls the `Coordinator Agent`. The Coordinator stores the expense in a short-term memory dictionary (keyed by session/ID) to allow follow-up questions. It then orchestrates a sequential, structured dictionary-passing workflow:
1. Calls `Policy Agent` (which queries `expense_policies.json` / Policy Tool) -> Returns policy_findings.
2. Calls `Receipt Agent` (which queries Receipt Tool) -> Returns receipt_findings.
3. Passes both to `Analysis Agent` -> Returns risk_analysis.
4. Passes analysis to `Decision Support Agent` -> Returns final advisory report.
The combined results are returned to the UI, preserving the strictly advisory "decision-support" tone. If any agent fails, the Coordinator catches the error, marks that agent's status as failed, and gracefully continues or provides a safe fallback.
